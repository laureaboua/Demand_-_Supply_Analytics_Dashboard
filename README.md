# 📦 Demand & Supply Analytics Dashboard 

## 📌 Project Overview

Businesses need to balance **customer demand** with **product supply** to avoid stock shortages, excess inventory, delayed deliveries, and lost sales. Poor inventory planning can increase operational costs while reducing customer satisfaction.

This project analyzes sales, inventory, purchasing, suppliers, shipments, warehouses, and external business factors to help decision-makers understand how demand and supply interact across the business.

Using **Microsoft Excel** for data preparation and **Power BI** for visualization, I built an interactive dashboard that transforms raw operational data into actionable business insights.

---

# 🎯 Business Problem

The company needed a way to answer questions such as:

* Which products are driving the most demand?
* Which products are running out of stock?
* Are suppliers delivering efficiently?
* Are inventory levels aligned with customer demand?
* Which regions generate the highest sales?
* Are delayed shipments affecting customer service?
* Which product categories contribute the most revenue?
* Where should management focus purchasing efforts?

Without a centralized dashboard, answering these questions required manually reviewing thousands of records from different datasets.

# 🧹 Data Cleaning (Microsoft Excel)

Before importing the data into Power BI, the datasets were cleaned in Microsoft Excel.

### Cleaning Process

* Checked for missing values.
* Removed duplicate records.
* Standardized column names.
* Corrected inconsistent formatting.
* Verified data types (dates, numbers, text).
* Ensured Product IDs, Customer IDs, Supplier IDs, Warehouse IDs and Category IDs were consistent across all tables.
* Reviewed transaction dates for accuracy.
* Removed unnecessary spaces and formatting inconsistencies.
* Prepared each dataset for relational modeling.

The cleaned datasets provided a reliable foundation for analysis and reduced the risk of incorrect dashboard insights.

---

# 🔄 Data Modeling

The cleaned tables were imported into Power BI and linked using common keys such as:

* Product ID
* Customer ID
* Supplier ID
* Warehouse ID
* Category ID
* Sale ID

This relational model allowed information to flow correctly between sales, inventory, suppliers, customers and shipments.
